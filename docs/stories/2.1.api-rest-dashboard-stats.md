## Story

**As a** desenvolvedor frontend,
**I want** uma API REST para KPIs globais do dashboard,
**so that** o frontend possa exibir estatísticas consolidadas do estado com resposta rápida.

---

## Acceptance Criteria

1. Endpoint `GET /api/dashboard/stats` implementado
2. Retorna em < 200ms (com 497 municípios)
3. Response inclui:
   - `totalMunicipios`: total de municípios do estado
   - `municipiosAtivos`: count com status ATIVO
   - `municipiosInativos`: count com status INATIVO
   - `municipiosAtrasados`: count com status ATRASADO
   - `indiceAntifomeMedio`: média do índice antifome
   - `totalConselhos`: total de conselhos
   - `conselhosAtivos`: conselhos com status ATIVO
   - `totalReunioesMes`: reuniões no mês atual
   - `selosDistribuidos`: total de selos concedidos
4. Paginação não necessária (agregação)
5. Cache implementado com TTL de 5 minutos
6. Autenticação JWT obrigatória
7. Documentação Swagger completa
8. Testes unitários do serviço

## Dev Notes

### Contexto do Projeto

API que alimenta a barra de KPIs do dashboard principal. Deve ser otimizada para resposta rápida pois é chamada frequentemente.

### Response Schema

```json
{
  "totalMunicipios": 497,
  "municipiosAtivos": 353,
  "municipiosInativos": 84,
  "municipiosAtrasados": 60,
  "indiceAntifomeMedio": 6.8,
  "totalConselhos": 412,
  "conselhosAtivos": 380,
  "totalReunioesMes": 145,
  "selosDistribuidos": 234,
  "timestamp": "2026-03-15T10:30:00.000Z"
}
```

### Queries Prisma (Exemplo)

```typescript
// Count por status
const ativos = await prisma.municipio.count({
  where: { status: 'ATIVO' }
});

// Média do índice
const media = await prisma.municipio.aggregate({
  _avg: { indiceAntifome: true }
});
```

### Performance

- Index em `status` do Municipio (já criado na Story 1.2)
- Cache para evitar queries repetidas
- Target: < 200ms com 497 registros
